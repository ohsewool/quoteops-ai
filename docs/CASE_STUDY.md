# 사례 연구 — 넓게 지은 것을 반성하고, 좁고 깊게 다시 지었다

> 이 문서는 [V2-00 제품 계약](v2/V2-00-PRODUCT-CONTRACT.md)(1,974줄)과
> [V2-10B 릴리스 리뷰](v2/V2-10-RELEASE-READINESS-REVIEW.md)의 증류다.
> 모든 수치는 그 두 문서에서 나오고, 여기서 새로 주장하는 것은 없다.

## 문제

B2B 가격 결정은 결재의 영역이다. 그런데 도구들은 대개 계산만 돕는다 —
**"누가, 어떤 고객 요청의, 어떤 견적 revision에 대한, 어떤 가격을 승인했는가"**가
시스템에 남지 않으면, 가격 사고가 났을 때 되짚을 계보가 없다.

## 제약

- 금액은 KRW이고 오차가 허용되지 않는다 — 부동소수점은 신뢰 경계 밖이다.
- 승인은 사람의 권한이다. AI가 개입하더라도 숫자와 상태를 건드리면 안 된다.
- 1인 개발 + AI 에이전트 협업. 넓은 표면을 같은 품질로 유지할 수 없다.

## 처음 지은 것, 그리고 감사에서 나온 것

V1은 넓었다: **API 99개(경로 74) · ORM 모델 19개 · 테스트 410개 전부 통과.**
견적 미리보기·후보 가격·검증·승인·시뮬레이션·비교·리포트가 코드와 테스트로
확인됐다. 초록불만 보면 완성품이었다.

출시 전 전수 감사에서 초록불이 말하지 않는 것이 나왔다.

- **핵심 결함 — 계보가 없다.** `CustomerQuoteRequest`는 있는데 영속
  `Quote`·`QuoteLine`·가격 후보·검증 결과가 없었다. 미리보기는 계산 응답만
  반환하고, **승인은 어떤 견적과도 연결되지 않았으며, 승인돼도 가격표는 바뀌지
  않았다.** 이 문제의 정의("누가 무엇을 승인했는가 추적 불가")가 바로 이 제품이
  풀겠다던 문제다 — 넓게 만드는 동안 자기 문제를 못 풀고 있었다.
- **보안 결함 여섯.** 공개 쓰기 API, 인증이 선택인 승인 변경, 무조건 시드 계정,
  `create_all()` 스키마 관리, UI로만 숨긴 권한, 약한 검토자 신원 결합.

## 선택한 설계 — 그리고 기각한 대안

**기각: 점진 리팩터링.** feature-flag로 V1 안에서 고쳐가는 안은 계보 없는 모델
위에 계보를 접붙이는 일이라 기각했다. **기각: 99개 API 동등 재구축.** 넓이가
문제의 원인이었다.

**채택: V1을 증거로 동결하고, 깨끗한 저장소에서 좁은 V2를 짓는다.**

- V1은 "demo/portfolio only"로 선언하고 실데이터 입력을 금지 문서화했다.
- Tier A(핵심 흐름: 요청→견적→점검→승인→리포트)만 V2 완성 계약에 넣고,
  Tier B 44개 작업은 V1에 동결한 채 남겼다 — 비목표를 계약에 명시했다.
- **승인이 견적 revision·가격 후보·검증 스냅샷에 영속으로 묶인다.** 이것이
  V2의 존재 이유다.
- **AI 경계:** copilot은 저장된 근거의 설명·요약·제안까지만. 숫자·상태 변경
  불가. 핵심 흐름은 LLM 없이 완주된다.
- **수치 경계:** Decimal 문자열만 수용. Float 유래 값은 반올림하지 않고
  **격리**한다(quarantine). V1 가격표는 V2 재계산과 0.01 KRW 안에서 일치할
  때만 증거로 보존한다.
- 시드 0 — 첫 관리자도 명시적 CLI로만.

## 검증

- **V2-01 보안 게이트 선통과**: 공개 쓰기 0 · 선택 인증 승인 0 · 시드 0 ·
  백엔드 역할 강제 · 마이그레이션 프레임워크 · Decimal 정책.
- 단계마다 구현 보고서와 **갭 로그**(못 한 것의 목록)를 남겼다 — V2-01부터
  V2-10까지 전부 저장소에 있다.
- **V2-10B 독립 리뷰**: V1→V2 이관 변환기를 수용/비지원/변형값/재계산
  드리프트/중복 활성 프로필/시크릿 필드 거부/실제 CLI 서브프로세스까지
  검증했고, 컷오버·롤백 런북을 별도 문서로 뒀다.
- CI는 실제 PostgreSQL 16을 띄워 백엔드 69개 전부와 프런트엔드 31개를 돌린다.
  DB 없는 환경에서는 통합 28개가 **명시적 사유와 함께** skip된다 — 조용한
  생략은 없다.

## 남은 한계

- Tier B 44개 작업은 V1에 동결된 상태다 — V2 품질로 재구축되지 않았고,
  그것이 계약이다.
- 보호된 워크플로의 시각 QA는 하지 않았다 — 사용자가 0명인 상태를 유지하는
  것이 원칙이라, 우회 계정을 만들어 확인하는 쪽을 거부했다.
- 배포 인스턴스는 휴면 상태다. 실데이터 컷오버는 런북만 있고 실행된 적이
  없다 — 실데이터가 존재한 적이 없기 때문이다.
