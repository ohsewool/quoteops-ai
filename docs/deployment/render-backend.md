# Render Backend Configuration

The V2 backend is a repository-root Python service. It uses pip-compatible,
pinned dependencies in `requirements.lock`; it does not use Poetry and does
not provide a `requirements.txt` compatibility file.

## Render settings

| Setting | Value |
| --- | --- |
| Root Directory | `.` (repository root) |
| Python version | `3.12` from `.python-version` |
| Build Command | `python -m pip install --upgrade pip && python -m pip install -r requirements.lock` |
| Pre-Deploy Command | `python -m alembic upgrade head` |
| Start Command | `python -m uvicorn backend.main:app --host 0.0.0.0 --port $PORT` |
| Health Check Path | `/api/health/ready` |

`/api/health` and `/api/health/live` are liveness endpoints. Render uses
`/api/health/ready` so a deployment receives traffic only after it can reach
the configured PostgreSQL application database.

## Required environment configuration

Keep these values in Render, not in Git:

- `QUOTEOPS_DATABASE_URL`: the V2 application PostgreSQL URL only.
- `QUOTEOPS_AUTH_SECRET`: generated by the Blueprint when absent, or supplied
  as an existing secret.
- `QUOTEOPS_CORS_ORIGINS`: the comma-separated, deployed V2 frontend origins.

The Blueprint sets `QUOTEOPS_ENVIRONMENT=production` and disables demo data,
docs, and OpenAPI. Do not set `QUOTEOPS_TEST_DATABASE_URL` in this service.
Do not use a V1 database or any `requirements.txt` build command.

## Applying the configuration

`render.yaml` targets the existing `quoteops-ai-backend` service and has
`autoDeployTrigger: off`. Committing the file does not deploy it. Before a
manual Blueprint sync or Dashboard update, verify that the service name and
all existing settings are correct. Apply the Build, Pre-Deploy, Start, and
Health Check values above without exposing database URLs or authentication
secrets.
